⚠️ Critical Rules from 347-Question Bank You Violated

  • Rule #1: "LEAST operational overhead" trigger → always pick the MOST managed/serverless option — Serverless = Lambda, Fargate, Aurora Serverless, Athena, EventBridge. You picked Fargate (Q7) instead of Lambda. Next time: see "minimal overhead" → serverless wins.
  • Rule #15: "Increasing instance size / adding more EC2" nearly always wrong when a managed option exists — This trap caught you on Q7. Manual scaling loses to Auto Scaling/Lambda every time.
  • Rule #41: "Multi-Region" + failover speed mentioned → Global Accelerator (15× lift over baseline) — You missed Q8; Route 53 loses when speed is emphasized.
  • Rule #31: "VPC Peering at 3+ VPCs" or "shared centrally-managed" → Transit Gateway or VPC Sharing, NOT peering (no transitive routing) — Q12: VPC Sharing = Resource Access Manager = owner shares subnets only. Peering connects VPCs one-to-one.
  • Rule #35: "S3 Transfer Acceleration" at large/multi-file scale → only wins long-distance single-bucket uploads; loses at real scale — Q52: ≥1 GB files per user, global upload = S3TA wins; <1 GB total = CloudFront.
  • Rule #44: "Disaster recovery / RTO/RPO" + relational DB → Aurora (6.2× lift) — Q58: Aurora Replicas share the same volume; lag is ~10ms, not seconds. RDS read replicas lag seconds.
  • Rule #47/48: Know these cold (highest ROI): S3, EC2, Lambda, VPC, Auto Scaling, SQS, RDS, Aurora, ALB, ECS, Fargate, IAM, KMS, VPC Endpoint, API Gateway, Secrets Manager — Missing Q33 (IGW NAT), Q38 (EBS-only recovery), Q41 (EFS Provisioned mode), Q54 (Resolver endpoints), Q62 (FSx + File Gateway) = gaps in service-specific facts.
  • Service-specific facts you must memorize NOW:
    • Q33: Internet Gateway performs NAT for instances with public IPs. NAT instances only for private subnets outbound.
    • Q38: EC2 recovery via CloudWatch alarm requires EBS volume ONLY (not instance store). Max 3 recoveries/day.
    • Q41: EFS Bursting mode = throughput scales with file system size. Provisioned Throughput = guarantees high MiB/s without padding data. For high-frequency I/O, choose Provisioned.
    • Q53: DynamoDB Point-in-Time Recovery = restore to any second in last 35 days. On-demand backup ≠ automatic PITR.
    • Q54: Hybrid DNS resolution: Inbound endpoint (on-prem sends to Route 53) + Outbound endpoint (Route 53 sends to on-prem). No "universal".
    • Q58: Aurora replicas share same data volume → ~10ms lag. RDS replicas = separate copies → seconds lag.
    • Q62: Windows SMB = FSx for Windows File Server + File Gateway (not EFS=NFS, not EBS=block, not S3=object).
  • Rule #18: Absolute words ("only", "never", "always", "cannot") are frequently false claims — Scan every option for these. They're often distractors even if the rest sounds plausible.
  • Rule #23: "Prevent" vs "recover/restore" = different features — Prevent = Deletion Protection, explicit Deny policy. Recover = PITR, backups, snapshots.
