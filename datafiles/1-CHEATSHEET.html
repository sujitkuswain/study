SAA-C03 Decision Rules & Cheatsheet

Mined from 1,019 questions (204 ExamPrepper PDFs). Every rule below is backed by how the answers actually behaved in this bank — counts are shown as [n].

0. How to read every SAA-C03 question

Three passes, in this order. Do not read options first.

  1. Find the qualifier. It's almost always in the last sentence, in CAPS: LEAST operational overhead, MOST cost-effective, MOST secure, LEAST effort. This is the tiebreaker between two technically-correct options. 42% of this bank has one.
  2. Find the hard constraints. Words that eliminate options outright: "must not traverse the internet", "cannot modify the application", "existing SMB shares", "single-digit millisecond", "12 months retention", "RPO of 5 minutes".
  3. Eliminate, don't select. Typically two options are obviously wrong, and the remaining two differ by exactly one word (FIFO vs standard, cached vs stored, gateway vs interface). That one word is the whole question.

Answer letters are uniform (A 21%, B 25%, C 22%, D 18%). Guessing by letter buys you nothing.

4. The eight pairs the exam keeps testing

Learn the one-word difference in each.

  1. SQS FIFO vs standard — FIFO only if order or exactly-once is stated. Standard otherwise (higher throughput).
  2. Multi-AZ vs read replica — Multi-AZ = availability, no read traffic. Read replica = performance, async.
  3. Gateway vs interface endpoint — Gateway = S3 & DynamoDB only, free, route-table. Interface = everything else, ENI, hourly cost.
  4. Volume Gateway cached vs stored — cached: primary data in S3, hot cache on-prem (limited local space). stored: all data on-prem, async backup to S3 (need full local copy + DR).
  5. SNS vs EventBridge — SNS = simple pub/sub fan-out. EventBridge = content filtering, AWS/SaaS event sources, schedules.
  6. Kinesis Data Streams vs Firehose — Streams = custom consumers, replay, ordering, shards you manage. Firehose = zero-admin delivery to S3/Redshift/OpenSearch/Splunk, ~60s buffer.
  7. CloudFront OAC vs bucket policy — OAC is how you keep the S3 bucket private while serving via CloudFront.
  8. Security group vs NACL — SG: stateful, instance level, allow-only. NACL: stateless, subnet level, can deny (the only way to block a specific IP).

6. Elimination heuristics that hold across this bank

  • Anything with "manually", "custom script", "cron job on EC2", "write your own" loses to a managed service when the qualifier is least overhead or least effort.
  • Access keys stored anywhere (env var, AMI, code, S3) is wrong. It's an IAM role.
  • Snowball for anything urgent is wrong — it takes days/weeks. It only wins on petabyte-scale with poor bandwidth.
  • Direct Connect for a one-time migration is wrong — provisioning takes weeks.
  • VPC peering at 3+ VPCs is wrong — no transitive routing.
  • Route 53 failover when the stem stresses speed of failover loses to Global Accelerator (DNS TTL caching).
  • EMR / Redshift / EKS are the three most common "sounds impressive, wrong answer" services in this bank.
  • Increasing instance size / adding more EC2 is nearly always wrong when a managed or serverless option is on the table.
  • "Enable versioning" protects against deletion/overwrite, but is not compliance-grade retention — that's Object Lock.
  • If two options are identical except one adds an unnecessary component, the simpler one wins.

7. Multi-select questions (12% of bank)

  • "Choose TWO" answers are usually one compute/network fix + one config/security fix — not two variants of the same idea.
  • If two options are near-duplicates, they're rarely both correct.
  • Count your selections against the stem before moving on — the exam does not warn you.
